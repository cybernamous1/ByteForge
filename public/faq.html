Frequently asked questions

Where is my code stored?

In your browser's IndexedDB (project and database) and localStorage (preferences) on this device. ByteForge has no servers that receive your files and no accounts.

Can I lose my work?

Yes. Clearing site data, a browser eviction under storage pressure, a different browser profile or a full disk can remove it. Use Download Project regularly and consider Settings → Request persistent storage.

Is ByteForge a full replacement for VS Code or a cloud IDE?

No. It is a browser workstation with a real editor, terminal, SQLite and a Node.js runtime where the browser allows it. There is no debugger, no extensions marketplace, no Git integration and no access to your computer's file system.

Does the terminal run real commands?

Before you start the runtime, it is a small built-in workspace shell that really modifies your project files but is not a POSIX shell. After you type run and accept the prompt, a real Node.js shell (WebContainers) is attached.

Why does the Node.js runtime say it is unavailable?

WebContainers need cross-origin isolation (COOP/COEP headers) and a supported desktop browser. Self-hosted deployments must serve the included _headers. Some browsers, private modes and most mobile browsers cannot run it.

Does ByteForge work on a phone, and in “desktop site” mode?

Yes, the editor, terminal, sidebar, preview and database panels are usable on touch screens. ByteForge detects phones even when the browser reports a desktop-sized page, and you can force a layout in Settings → Layout. Pinch-zoom is never disabled. The Node.js runtime is the exception: WebContainers are not officially supported on mobile browsers, so it may not start there.

Is “localhost” in the preview my own computer?

No. A server started in the Node.js runtime runs inside an in-browser sandbox and is shown as “sandbox localhost:PORT”. It is reachable through its preview URL while this tab is open. It is not a server on your device, and servers on your device are not started or exposed by ByteForge.

What languages can I run?

JavaScript (isolated worker or Node.js runtime), Python (Pyodide, experimental), SQL (SQLite), HTML/CSS/JS in the static preview, and anything Node.js can run inside the runtime. Other languages get syntax highlighting only.

Does anything leave my browser?

Not by default. Network requests only happen when you choose to: starting the Node.js runtime (StackBlitz servers; npm registry for npm install), running Python for the first time (jsDelivr), or when your own code makes requests. See the Privacy Policy.

How does secret detection work?

Local pattern matching on file contents, shown in the Problems panel and in the export dialog. It is heuristic, so it can miss secrets and can flag harmless text. Never treat ByteForge as a secret vault: browser storage is not encrypted.

Can I use a real PostgreSQL/MySQL database?

Not through Database Studio, which is SQLite only. Inside the Node.js runtime you can use packages that work in the browser sandbox, but network access and native modules are restricted by WebContainers.

Can I work offline?

Once the page is loaded, the editor, files, JavaScript runner, SQLite and static preview work without a network connection. The app does not install a service worker yet, so it cannot be reopened offline after closing it.

Can I share a project?

Download the ZIP and send it, or import it on another device. There is no link sharing or sync.

Is ByteForge free for commercial use?

ByteForge itself imposes no fees, but its components have their own licenses; in particular WebContainers may require a commercial license from StackBlitz. See Documentation → Third-party components.
